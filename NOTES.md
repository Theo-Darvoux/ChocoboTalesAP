# Chocobo Tales apworld: dev notes

## Layout

- `chocobo_tales/`: the apworld package
  - `data.py`: generated from the ROM by `tools/extract_rom_data.py`. Don't edit it by hand.
  - `flags.py`: what each save flag means. `ram.py`: where the flags live, and which flag each location /
    item uses.
  - `rom_patch.py`: builds the Archipelago ROM (no Archipelago imports). `rom.py`: the `.apcts` patch file.
  - `hooks.py`: the assembled flag-write hooks, generated by `tools/assemble_hooks.py`. Don't edit it by hand.
  - `nds.py`: a verbatim copy of `NDSTools/ndstools/rom.py` (the apworld must be self-contained; a test
    checks they match)
  - `rewards.py`: which location each vanilla reward message stands for (location ids live here).
    `reward_patch.py`: rewrites the reward texts per seed. `ap_card.py`: builds the Archipelago card.
    `text_patch.py`: .act / MGNNN.dat / .ptx editing. `font.py`: a verbatim copy of `NDSTools/ndstools/nftr.py`
    (NFTR metrics, wrapping, glyphs; a test checks they match). None of these import Archipelago.
- `tools/extract_rom_data.py`: regenerates `data.py` (`python3 -I tools/extract_rom_data.py <rom> chocobo_tales/data.py`)
- `tools/assemble_hooks.py`: regenerates `hooks.py`. Needs keystone, so run it with `../NDSTools/.venv/bin/python`.
- `tools/act.py`: field event script (`.act`) parser. Run it on the ROM for an opcode summary.
- `tools/new_game.py`: drives a fresh boot to the chapter 1 field through the NDSTools bridge
- `tools/inject_ap_rewards.py`: shows a seed's reward texts in a savestate made on the vanilla ROM (see "Testing
  reward texts" below), through NDSTools' `inject`. Graphics: `python3 -m ndstools gfx ROM /card/card_0100.pbg.z
  out.png --screen /card/card.NSCR.z --crop 0,0,128,192`; fonts: `python3 -m ndstools font ROM /text/font.nftr TEXT`.
- `tests/`: `test_ram` (stdlib: `cd tests && python3 -m unittest test_ram`), `test_rom_patch` (needs the ROM
  and unicorn: `cd tests && ../../NDSTools/.venv/bin/python -m unittest test_rom_patch`), `test_reward_patch`
  (needs the ROM), `test_rom_procedure`
- `research/`: the research BizHawk instance (its own config, saves, states), built ROMs, screenshots. Local only
  (git-ignored: it holds ROMs and savestates).
- `presets/`: the YAML presets attached to releases. `tests/test_presets` keeps them generic (`Player{number}`,
  one fixed value per option).
- `.github/workflows/`: `ci.yml` runs the unit tests and generates every preset with Archipelago 0.6.7 and 0.6.8;
  `release.yml` publishes a release when a `v<world_version>` tag is pushed.
- `build.sh`: builds `chocobo_tales.apworld` and copies it to `~/.local/share/Archipelago/worlds/`

The generic tools (ROM reading/rebuilding, disassembly, the BizHawk bridge, RAM search) are in `../NDSTools`.
The ROM is `~/Applications/ROMs/NDS/FFF_ChocoboTales_Europe.nds`.

## Memory map (EU, AEHP)

Everything was found by static analysis (`NDSTools`), then checked in game.

- **Save struct**: the global at `0x0209DDE0` points to it (`0x020A35D8`). The new-game code at
  `0x020014FC` sets it up. Loading a save copies SRAM slot data into it. The live game state *is* this
  struct; saving serializes it back to SRAM (SRAM `0x38` = struct `+0x00`).
- **Flag bank** at struct `+0x24`: 32-bit words, flag n = bit (31 − n % 32) of word n / 32.
  API: test `0x02001BBC`, set `0x02001BE8`, clear `0x02001C08`, get field `0x02001C28`,
  set field `0x02001C4C`. Only these wrappers call the low-level bit functions (`0x020041E0`…), so hooking
  the set / set-field wrappers covers every flag write in the game.
- **Storybook goals**: overlays 3-16 set `0x7EE + 32k + goal` (k = book − 1, goal 0-6 in the in-game list order).
- **Chocobo rescues**: the 15 storybook goals awarding a chocobo each have a separate rescue check on that
  goal's completion flag. This works even when the goal is excluded from the selected storybook checks;
  receiving the corresponding Archipelago Chocobo item only sets its blocked ownership flag.
- **Storybook rewards** (applied by overlay 53 at `0x020D3E0C` from `/mgame/result/*/MGNNN.dat`):
  type 0/5 battle levels (bitmask, flag `0x7DD + 32k + level − 1`), 1 epilogue (`0x7D7 + 32k + e`),
  2 trial mode (`0x7E2 + 32k`), 3 card (`0x400 + card number`), 4 chocobo (`0x3E6 + friend id`).
  The reward data includes unlocks the reward text doesn't show (e.g. book 3's first goal also unlocks trial mode).
  Book 1's battle-level flags are never blocked and have no Modes item: its first solo goal unlocks Battle
  Level 1, and Irma won't let you leave the starting area before that duel. The client restores those flags
  from completed book 1 goals for older saves and seeds (which may still send the retired item 301).
- **Storybook available**: `0x7E3 + 32k`.
- **Microgames**: overlay 22 + m runs microgame m. Flags `0x9F8 + 3(m − 1)` +0 first play, +1 Silver, +2 Gold.
  Each overlay's thresholds match the ROM's Silver/Gold texts.
- **Cards**: card n owned = flag `0x400 + n`. Checked in game: setting the flags makes the cards appear in the
  collection.
- **Field card pickups**: nine `cardget.act` scripts set separate pickup flags (`0x8D`, `0x8E`, `0x9E`,
  `0xA0`, `0xA1`, `0xAF`, `0xBD`, `0xE7`, `0xEA`) as well as their card ownership flags. The ownership
  writes are blocked by the patch; the pickup flags remain writable and drive nine checks.
- **Story**: chapter N + 1 opens with flag `0x43 + 2(N − 1)` (`0x43`, `0x45`, `0x47`, `0x49`, `0x4B`). Each
  is set by the chapter's opening script right after the Bebuzzu duel. The ending sets `0x3DF`.
- **Duels**: `0x7C8` is the successful duel result, not a separate performance rank. Overlay 19 at
  `0x020CC268` compares the original selected duelist pointer (`+0x3440`, assigned at `0x020CB764`)
  with the surviving duelist pointer (`+0x3448`, assigned from the survivor search at `0x020D22EC`),
  and checks that a duel configuration is present (`+0x46B0`). No HP or score equality is tested.
  The boss tiles' `DuelResultS.act` set `0x13E`-`0x145` on a win; `DuelResult.act` only warps back.
  Optional location names now say "Pop-up Duel Win"; the YAML key `duel_s_rank_checks` stays for compatibility.

## USA release (AEHE)

`~/Applications/ROMs/NDS/chocobotalesusa.zip` (MD5 of the NDS: `06d12ca36fcd88c32c276affe792ae61`). Same game
data: `tools/extract_rom_data.py` gives the same `data.py` but for 43 field grants' message table offsets, which
nothing reads. Differences the patch handles (`rom_patch.VERSIONS`):
- ARM9: the set / set-field wrappers are at `0x02001B6C` / `0x02001BD0` (EU minus `0x7C`, same bytes), calling
  `0x020040A4` / `0x020041A0`; they load the save pointer global `0x0209DBF8` (literal `0x0209DBF4`). `ndstools
  calls` finds no other caller of the low-level functions, as in EU. Same ITCM autoload block (`0x01FF8000`,
  `0x6D00`), so the hooks only differ in their literal pool (`hooks.CODE` per game code).
- English only: one `/mgame/result/en`, `/mgentryphase/text/en`, `/card/en` folder. `.act` text tables keep seven
  entries (0, 4, 6 Japanese, 2, 3, 5 French/German/Spanish leftovers); the patch points all seven at the English
  text. The only English monster name with an "A" is the condensed "Adamantoise", so `ap_card.harvest_letters`
  takes a missing letter from the first piece of such a name.
- Overlays 2/19/53 load at `0x020CAD80` (EU minus `0x1E0`); overlay 53 has the same `card\&\card.bin.z` path.
The patched EU ROM is byte-identical to the one built before this port. The same `.apcts` applies to either ROM
(`build_ap_rom` picks the version from the game code; Archipelago only records the manifest's checksum), and the
client picks the save pointer from the cartridge header. Tested: both ROMs through `test_rom_patch` (hooks run in
unicorn) and `test_reward_patch`, a generated `.apcts` applied by Archipelago 0.6.7's `Patch.py` to the US ROM, and
the client's version detection. Not yet run in BizHawk.

## Field event scripts (.act)

A u32 string-area offset, then commands: u16 opcode, u16 length, 8-byte arguments (u16 type, u32 value).
Argument types: 1 immediate, 2 code offset, 4 flag field (flag | width << 16), 8 variable, 0x40 per-language text.
Known opcodes: 0x00 assign (dest, src), 0x05 message, 0x0A start scene (mode, id, return label),
0x0B jump / message, 0x23 door transition, 0x29 warp to map tile (x, y).

Scene modes: 0 storybook (id = book − 1), 1 microgame (id − 0x10 = microgame number, ids 0x11-0x27),
2 Pop-up Duel, 3 chapter / story scenes (ids 2-6 are the chapter 2-6 title cards, 13 the ending).

Story order comes from the developer skip scripts `/field/50/50/skipN[pb].act`. skipN is the state right after
chapter N − 1's Bebuzzu duel (it has that boss scene's story flags, e.g. `0x34`/`0x3F` from `45/51/a3.act` in
skip3), so its storybooks belong to chapter N − 1; skipNpb is a point inside chapter N. Their chapter flags are not a
reliable marker (skip3/skip4 lack the one the boss scene sets, skip5 has it). Each chapter 2-5 boss is started by
epilogue 1 of the boss tile's storybook: Gimmick4B1 (book 8), 5B1 (book 10), 6B1 (book 12) and 8B1 (book 16) warp
into the scene (`45/51/a2`, `48/55/a1`, `56/51/a3`, `44/45/a1`) that sets the guard of the tile's `bebuz.act`.
These are `access.BOSS_EPILOGUES`, required by each "Chapter N Complete". Books 14 and 16 are in no skip script:
book 14's object at 47/45 needs Gimmick8A1's `0x60` (in skip5pb), book 16 starts chapter 5's boss, so both are
chapter 5. `tools/extract_rom_data.py` reads which storybooks the skip scripts unlock. Microgame locations
come from the field map marker table in overlay 2 (`0x020D684C`: 16 storybooks, 14 duels, 23 microgames with
their map tiles) and from their launch scripts.

## ROM patch

`rom_patch.patch_rom` decompresses the ARM9 binary and appends 0x260 bytes to its ITCM autoload block (hook
code + a bitmap of blocked flags, at `0x01FFED00`). It redirects the set / set-field wrappers to the hooks and
rebuilds the ROM with `nds.build_rom`. Blocked flags = every flag an Archipelago item sets (`ram.ITEM_FLAGS`).
The client sets those flags by writing RAM directly. The slot name is at ROM `0x1010`, after the magic
`APCHOCO\x01` at `0x1000` (unused space between the header and the ARM9 binary).
When Shuffle Epilogues is enabled, the patch procedure also blocks 48 epilogue flags (`0x7D7 + 32k + e`,
`e=1..3`). The `.apcts` stores a per-player `shuffle_epilogues.bin` byte; `build_ap_rom` reads it before
assembling the blocked bitmap. With the option off, the game still grants epilogues normally.

Tested: the earlier rebuilt ROM reached the chapter 1 field; the hooks let story flags through and block listed
flags, both in game and by emulating the patched code with unicorn for every blocked flag. Unit tests also
check that the epilogue bitmap changes per option. The new option combination has not had a live emulator run.

## Reward messages and the Archipelago card

The patch makes every place the game announces a blocked reward name the Archipelago item at that location instead
(the item name only, not its player), in all five languages. `generate_output` writes `location_items.json`
(location id -> item name) into the `.apcts`; `build_ap_rom` passes it to `patch_rom`. Patches without it keep
the vanilla texts.

- **Field scripts**: 90 card grants in field scripts (`data.FIELD_CARD_GRANTS`, extracted from the ROM). Each
  "You obtain the NNN ... pop-up card" message becomes "Item found:" + the item (wrapped with the dialogue font's
  widths, 205 px, 3 lines; unknown characters transliterated or "?"), or "there is nothing to obtain here" when
  the location isn't in the seed. Text arguments (type 0x40, opcodes 0x0B message and 0x24 choice) point to 7 u32
  offsets of UTF-8 strings: JP, EN, FR, DE, IT, ES, JP. New strings are appended; text may contain 0xFF-based
  control codes (page breaks, player name), decoded with surrogateescape.
- **Which location a message stands for**: microgame result scripts (`LGRESULT*.act`) guard each card message
  with an op 0x05 condition. Conditions are postfix expressions; a flag reference is `04 00 00 00 <flag> 01 00`.
  The medal flag in it (`0x9F8 + 3(m - 1) + 1/2`) gives the microgame and medal, so all 46 medal cards map to the
  existing medal locations (Cid's machines run the same microgame from several tiles). `cardget.act` = field card
  locations. Everything else is a **card gift** (27 cards: Carbuncles, Peachie, Becky, Grinn, Bruce, Chubby,
  Jailbird, the Mist Dragon in the hole at 48/51, Dueler X's Goblins and Moogle card, the Typhon chests, the beaten
  duelists, and Gungnir+ / Karma+ for beating all four Pop-up Duel bosses / Bebuzzu duels). Each gift script sets
  an event flag (0x81-0xFA) right before the card flag; that flag is the check. The ending flag `0x3DF` selects
  dialogue or music in several gift scripts; it does not guard their card grants.
  `access.py` now places 26 gifts in chapters 2-6 with their rescued-chocobo and field-gimmick requirements. The
  first-duelist cards belong in chapters 2/3/4/5; the skip3/4/5 snapshots contain their story flags `0x28`/`0x4E`/
  `0x6C`, and Iron Giant is fought in chapter 5 (touching book 14 runs `47/45/a1.act`, which sets its guard `0x7B`). `DuelResultS.act` sets their four win flags and awards Gungnir+
  once all are set, so that gift is in chapter 5 too. Dueler X's Goblin cards are part of chapter 2's forced event.
  Dark Blade checks ownership flags for all chocobos 3-20: 15 are Archipelago items, while Gelp, Bluebay and Rose
  are fixed story rescues. Rose's map tests story flag `0x72`, present by the chapter 5 skip snapshot, so the gift
  is placed in chapter 5. Carbuncle 77 (149/49) needs `0x34`, set by the chapter 2 boss scene `45/51/a3.act`, so it is chapter 3.
  Carbuncle 78 appears on Technolith 5F when `0x7F` is set after the chapter 5 Bebuzzu
  duel; Carbuncle 76 appears in the barn when the other five Carbuncle flags `0xC9`-`0xCD` are set. Neither map
  creation guard tests the ending flag, and the corresponding flags stay set across chapters. Both belong to
  chapter 6. Only Karma+ remains in Post Game: its Bebuzzu rematches are offered after the ending.
- **Chocobo rescue scenes** (`cNN.act`, "You rescued X from the chocobo card!") are left as they are: each book's
  `bookret.act` only plays them once the chocobo's ownership flag is set, which only the Archipelago item does.
- **Storybook result screens**: `/mgame/result/<lang>/MGNNN.dat` is 7 x (u32 goal text, u32 record count,
  u32 records), then records (u32 type, u32 text, u32 value); offsets are absolute. (The extractor's older reading
  as count/records/text happens to give the same records.) Records setting a blocked flag are removed and one type 3
  record per location the goal checks (goal, then chocobo rescue) shows the Archipelago card with "Item found:" +
  item. Unblocked records (book 1 battle levels, unshuffled epilogues) stay. Type 3 sets flag 0x400 + the card's
  number, found by image id in overlay 53's own copy of card.bin (linear search, `0x020D5488`).

- **Goal lists**: `/mgentryphase/text/<lang>/secret/clNNN.ptx` (`\x1bC` card icon, `\x1bG ... \x1b\x1b` color).
- **The Archipelago card** (image id 2700, number 0; `ALWAYS_BLOCKED` adds flag 0x400): the result screen draws
  the whole card face from `/card/card_<id>.pbg.z` (D2KP: NCLR + 8 bpp NCGR, laid out by `/card/card.NSCR.z`),
  the name from `/card/<lang>/name_<id>.NCGR.z` (64x32, card palette, gray ramp 0xE0-0xEF) and the description
  from card.bin (UTF-8, 0x1C n colors). Built when patching from the player's ROM: the Chocobo promo card's frame,
  the Archipelago logo drawn as pixel art in its picture window (`in_picture`, checked against all 127 cards), and
  the name written with letters cut out of the 635 vanilla name images (median of the most common width per letter).
  card.bin gets the extra entry in a copy, `/card/<lang>/apcd.bin.z`; overlay 53's path string is patched to read it
  (stored uncompressed), so the collection, decks and duels never see it.
- **New files**: `nds.build_rom(new_files=...)` adds files to existing directories by giving each such directory a
  new file id range at the end of the FAT; old ids still point at the same data. Checked in game: the collection
  loads card.bin, names and pictures through the moved `/card/` folders.
- ROM size: the base patch already stores the ARM9 binary uncompressed (67.26 MB, a 128 MB cartridge in the
  header); the reward patch adds about 160 KB.

### Testing reward texts

BizHawk refuses a savestate made with another ROM ("MemoryBlock hash mismatch"). To show patched data in the
user's vanilla states, `tools/inject_ap_rewards.py` loads the state with the vanilla ROM and writes the changed files
into the 0xFF padding at the end of the cartridge ("ROM" domain), pointing their FAT entries there, both on the
cartridge and in the FAT copy the game keeps in Main RAM (`0x020F90C0` in those states). A file already loaded
(e.g. a running script) isn't affected. Only about 127 KB is free, so it injects a subset; the Archipelago card
stands in for image id 2600 there.

Verified in game this way (French): the field card at 150/49 (vanilla state before picking it up) shows "Objet
trouvé : <item>"; finishing book 1's race under 30 s shows the Archipelago card (logo, name, description) and
"Objet trouvé : <item>". The full patched ROM boots to the chapter 1 field (`research/states/full_ap_chapter1.State`).
Not yet seen in game on the full patched ROM: the goal list, a microgame medal or gift message, a chocobo or
epilogue result, and overlay 53 loading `apcd.bin.z` itself (structurally tested; the same folders' files load
fine). A vanilla SaveRAM loads with the full patched ROM, but its last persisted point precedes these results;
the near-result vanilla savestate cannot be loaded under a different ROM hash.

## Options and generation

- `presets/chocobo_tales.yaml` is a commented template with weighted examples. Its five goals include counts of
  actual completed storybook-goal flags and Gold-medal flags in the client; the generation solver checks that
  enough corresponding locations can be reached.
- Card Packs are 26 monster-specific items that set all 127 card flags. Logic counts the cards inside each
  pack toward the 15-card deck requirement and Card Collection. Starting Cards rounds up to whole packs.
- Open Storybook Modes and Starting Chocobos precollect their items. The first 2–7 goals per book can be
  selected; the older `exclude_hardest_storybook_goals` key caps this at 4, but goal order is not a proven
  difficulty ranking. Silver, Gold, or both microgame medal checks
  can be selected. Invalid item/check counts now fail with a clear error instead of silently precollecting
  extra cards. `presets/` has separate full, Compact, and Epilogues presets.
- `field_card_checks` and `chocobo_rescue_checks` independently enable the nine field card and 15 rescue
  locations. Both default to true and are explicit in all three YAML presets.
- Universal Tracker: slot data carries every game option (not the common ones), and `generate_early` reads
  them back from `re_gen_passthrough`, so no YAML is needed. Logic depends only on options; the random
  starting items aren't precollected on regeneration because the server sends the real ones.
- Generated a one-player weighted-template seed and two mixed five-player seeds (story, rescue, cards,
  storybook goals, medals) with the updated apworld in an extracted Archipelago 0.6.7 test copy. The five `.apcts`
  files contain the expected per-player epilogue bytes.

After the item-pool audit, added explicit 2–7 storybook goals per book, removed silent overflow precollects,
and made Card Collection/Chocobo Rescue reject goals already met by chosen starting items. Three safe YAML
presets now cover individual cards, compact Card Packs, and shuffled epilogues. All three presets and a mixed
five-player seed generated in the extracted 0.6.7 copy; an intentionally oversized pool failed with the
expected error. Current and old-format `.apcts` files applied through Archipelago's BizHawk client and
produced NDS ROMs. The resulting epilogue bitmaps had 0/48, 48/48, and 0/48 flags blocked respectively.
The client could not connect to BizHawk in this sandbox (`PermissionError: Operation not permitted`), so
live item delivery and access tests are still outstanding. Chapter transitions now reference reachability
of the previous chapter-complete check, but that check still uses card-count combat logic; it does not prove
whether other in-game flags or obstacles are required before a boss appears.

With reward messages and card gifts (2026-10-13): three three-player seeds of the Full, Compact and Epilogues
presets, a No Gifts + Chocobo Rescue / Gold medals pair (three seeds) generated in the extracted 0.6.7 copy
(`/tmp/squashfs-root`, with the new apworld in its `lib/worlds`). Its BizHawk client applied a Full `.apcts`; the
resulting ROM's field, microgame, gift and result texts match the spoiler.

Preset balance (2026-10-13, Archipelago 0.6.7, five solo seeds per preset and goal, all generated): the
presets use fixed values (the client never tells players which goal a weighted YAML rolled).
`chocobo_tales.yaml` (the defaults): 214 checks, 72 filler (33%), 6-8 spheres. `chocobo_tales_compact.yaml`:
84 checks, 31-34 filler (36-40%); card gifts are off there, since with the old logic 27 of 111 checks were post-ending and
filler reached 52-54%. `chocobo_tales_epilogues.yaml`: 166 checks, 65-68 filler (39-40%).
Storybook Goals and Gold Medals defaults are set so those goals need chapter 5, like most of the story. Since the
story-order fix (books 3, 7, 8, 10, 12, 13 a chapter earlier, 14 and 16 in chapter 5), chapters 1-4 hold 12 books
and 16 microgames (with their chocobo hosts). Storybook Goals Required is 90 (> 84 = 12 x 7; was 75 for the old
70), Compact asks 26 (> 24 = 12 x 2; was 24), Epilogues keeps 50 (> 48 = 12 x 4), and 19 Gold Medals stays above
16. `test_access` checks the presets against these counts. Solo spheres are too coarse to show this: nearly
everything opens within two spheres.
